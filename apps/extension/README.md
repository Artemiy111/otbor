# @otbor/extension

Расширение для Chrome и Zen/Firefox (MV3). Без фреймворка: `bun build.ts`
собирает одни и те же исходники в `dist/chrome` и `dist/firefox`.

- **Страница вакансии** (`/vacancy/<id>`): состояние страницы (`HH-Lux-InitialState`)
  разбирается теми же парсерами, что и в CLI (`@otbor/hh`), вакансия уходит в
  `VacanciesUpsert`, затем считается решение (`VacanciesEvaluate`). Справа внизу
  панель: сопроводительное, тест, решение/fit, отклики, чёрный список.
- **Поиск** (`/search/vacancy`): карточки сохраняются как заглушки, рядом с каждой
  появляется плашка из базы (fit, письмо, тест, «откликнулись»).
- **Форма отклика** (`/applicant/vacancy_response` или попап на странице вакансии):
  если в otbor есть черновик (письмо и ответы теста), он вставляется в пустые поля
  сам, один раз на форму; черновик выбирается по резюме, выбранному в форме.
  Ничего не нажимается, кроме «Добавить сопроводительное» — отправляете вы.
  После вашей кнопки «Откликнуться» (или «Отправить» письма к уже отправленному
  отклику) и ответа hh «Вы откликнулись» содержимое формы сразу уходит в
  `ApplicationsRecordBrowserSubmit`: черновик становится `submitted`, а без
  черновика создаётся отклик `origin = imported`. Cloud сам проверяет разметку
  ответа; если отклик уже отправляет otbor (`queued` с задачей, `submitting`),
  запись не трогается.
- **Аккаунт вкладки.** В одном браузере могут быть разные аккаунты hh (контейнеры Zen).
  Расширение берёт `hhid` пользователя страницы (состояние hh, иначе главная того же
  контейнера) и передаёт его в cloud: `otbor hh login` хранит сессию аккаунта как
  `hh_<hhid>`, так что черновики и запись отклика относятся к аккаунту этой вкладки.
- **Открыть форму с черновиком** (настройка в popup, по умолчанию включена): на странице
  вакансии, где у аккаунта вкладки есть неотправленный черновик, расширение один раз
  открывает форму отклика — переходом по адресу `/applicant/vacancy_response?vacancyId=…`,
  а не кликом по «Откликнуться» (клик на вакансии без формы откликается сразу). В форме
  выбирается резюме черновика, нажимается «Добавить сопроводительное» и вставляется письмо.
- Все запросы идёт через background по тому же `RpcGroup`, что и веб и CLI; новый
  только `VacanciesLookup` (чтение).

## Разработка и установка

Сборка и dev — на WXT (`wxt.config.ts`), точки входа в `src/entrypoints`.

```bash
otbor extension dev                    # Zen с горячей перезагрузкой (отдельный профиль)
otbor extension dev --browser chrome   # то же в Chrome
otbor extension install                # собрать и поставить в Zen + подготовить Chrome
bun run extension:install              # то же из корня, только Zen (с перезапуском)
```

- Zen: XPI кладётся в основной профиль, `user.js` разрешает неподписанные дополнения; нужен перезапуск Zen.
  В MV3 Firefox доступ к сайтам не выдаётся сам: `about:addons` → otbor → Разрешения → hh.ru и 127.0.0.1.
- Chrome основного профиля автоматически не ставится (Chrome 137+): один раз «Загрузить распакованное»
  из `apps/extension/.output/chrome-mv3`, дальше Chrome помнит папку.

Адрес API (по умолчанию `http://127.0.0.1:3001/rpc`) и веба меняются в popup.
