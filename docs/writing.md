# otbor: письмо, ответы и резюме

Облако не вызывает модель: оно собирает промпт из своих строк и ставит
inference-job, текст пишет агент на стороне харнеса. Промпты собирают чистые
функции из `packages/cloud/src/writing/prompts.ts`. Каждая возвращает
`WritingPrompt { system, user, language, promptVersion }`, у каждой есть
русский и английский вариант.

Промптов два:

- **Черновик** (`draft-v3`): сопроводительное письмо и ответы на тест
  работодателя за один вызов. Им пользуются веб (`DraftGenerate`,
  `DraftPromptPreview`), автопилот (`AutoApplyRunner`) и CLI
  (`otbor write draft`). Другого промпта для письма или ответов нет.
- **Резюме** (`resume-v2`, `WritingResume`): переписывает текст резюме под
  целевую роль, не меняя факты.

## Черновик

`WritingService.loadDraftPrompt` загружает:

1. hh-аккаунт: имя соискателя (`APPLICANT`), а если имени нет, то метку;
2. вакансию: заголовок, работодателя, описание и навыки;
3. текст резюме и `resume_enrichment`: комментарий, зарплаты, ответы FAQ,
   комментарии, причины ухода и формат по местам работы. Всё это идёт в
   `APPLICANT NOTES`; `currentlyEmployed` (или открытая дата в опыте)
   определяет `EMPLOYMENT`;
4. форму вакансии и подсказки `hintsFor` к ней.

Вопросы попадают к модели не все. Задачи на код соискатель решает сам. Вопрос
с жёсткой подсказкой (удалёнка, зарплата текстом, офис, переезд) отвечается
подсказкой без модели. Мягкая подсказка показывается под вопросом строкой
`hint:`. Подсказку «работали с X? → да» модель не видит: это решает правило
промпта про технологии.

Правила промпта коротко:

- технология из вакансии, которой нет в источниках, называется знакомой, только
  если есть близкий аналог или её можно освоить за неделю; иначе в письме её
  нет, а на вопрос «работали с X?» ответ честный;
- письмо не пересказывает резюме и не перечисляет достижения из него, а общими
  словами говорит, почему соискатель подходит: технологии и задачи из
  вакансии, интерес к сфере или продукту; просьбы работодателя к письму
  важнее всего остального;
- без фактов о соискателе модель не выдумывает: в вопросе с вариантами выбирает
  самый правдоподобный, текстовый ответ оставляет пустым, и такой отклик ждёт
  человека.

`length` задаёт потолок письма: `short` (по умолчанию) — 400 знаков,
`medium` — 700, `long` — 1000. Ответ модели — один JSON-объект
`{ letter, answers: [{ questionId, optionIds?, text? }] }`; его проверяет
`parseGeneratedDraft` из `@otbor/domain` по настоящей форме.

`harness` в `DraftGenerate` необязателен: без него job берёт харнес по
умолчанию, как автопилот без настроенного писателя.

## CLI

Команды ходят в тот же RPC, что и веб, поэтому нужен запущенный сервер
(`otbor up`).

```bash
otbor write draft <application-id>
otbor write draft <application-id> --length medium --harness opencode --save

otbor write resume ./resume.txt --target-role "Platform Engineer" --language en
cat resume.txt | otbor write resume --target-role "SRE"
```

`write draft` берёт вакансию, аккаунт и резюме из заявки и печатает письмо, а
под ним каждый ответ со своим вопросом. Замечания разбора (`note: …`) идут в
stderr. `--save` заменяет только письмо в уже существующем kit заявки, ответы
kit не трогает: их собирает автопилот или веб вместе с подсказками.

Общие флаги: `--model`, `--timeout` (секунды, по умолчанию 180), `--no-wait`
(поставить job и напечатать id), `--json`. У `write draft` есть ещё
`--harness` и `--effort`, у `write resume` — `--language auto|ru|en`.

Сохранение никогда не отправляет отклик.
