# otbor: письма, ответы и резюме

Статус: черновик. Дата: 02.11.2026.

Документ описывает ACP-поддержку письменных задач: сопроводительное письмо,
ответы на вопросы работодателя и переписывание резюме. Облако только собирает
контекст и ставит inference-job; текст генерирует агент на стороне харнеса.
Браузерный заполнитель форм в эту задачу не входит.

## Контракт

В общую группу `OtborRpcs` добавлены три вызова. Все они возвращают
`{ job: HarnessJob }` и не ждут ответа модели.

| Вызов | Payload |
|---|---|
| `WritingCoverLetter` | `applicationId`, `tone?`, `length?` (`short`/`medium`/`long`), `model?` |
| `WritingAnswers` | `applicationId`, `questions: string[]`, `model?` |
| `WritingResume` | `text`, `targetRole?`, `model?` |

`model` уходит в `InferencePayload`; без него харнес использует модель по
умолчанию. `tone` и `length` влияют только на текст промпта.

## Что загружает облако

`WritingService` работает в пользовательской транзакции и берёт только то, что
принадлежит пользователю:

1. заявку (`application`) и проверяет владельца;
2. вакансию: заголовок, работодателя, описание и навыки;
3. текст резюме из `resume.text`, если у заявки есть `resumeId`.

`resumeId` может быть `null`: письмо и ответы тогда строятся без резюме, и
промпт прямо запрещает выдумывать опыт. Если `resumeId` задан, но строки нет,
это `NotFound` для `Resume`, а не молчаливая генерация.

Переписывание резюме не читает базу: текст передаётся в запросе. Job
привязывается к hh-аккаунту по умолчанию, как это делает `InferenceEnqueue`.

## Промпты

Промпты собираются чистыми функциями в
`packages/cloud/src/writing/prompts.ts`, поэтому их можно проверять без
Postgres и без вызова модели.

Общая системная инструкция `WRITING_SYSTEM_PROMPT` запрещает выдумывать
работодателей, даты, образование, метрики и навыки, требует писать на языке
вакансии или резюме и не использовать emoji, восклицательные знаки, длинные
тире и markdown-обёртки.

- **Письмо.** Вакансия (заголовок, работодатель, описание, навыки), резюме,
  тон и длина. Явно сказано вернуть только текст письма, без темы, шаблонных
  заглушек и комментариев.
- **Ответы.** Тот же контекст плюс нумерованные вопросы. Ответ должен быть
  JSON-массивом `{ "question": "...", "answer": "..." }`, по одному объекту на
  вопрос, в том же порядке, без markdown. Если факта нет в резюме, промпт
  требует сказать об этом, а не придумывать.
- **Резюме.** Исходный текст и целевая роль. Запрещено менять работодателей,
  должности, даты, образование и числа; можно менять формулировки, порядок и
  акценты. Вернуть только новый текст резюме.

## CLI

Команды ходят в тот же RPC, что и веб-клиент, поэтому нужен запущенный сервер
(`bun run server`) и `OTBOR_API_URL` (по умолчанию
`http://127.0.0.1:3001/rpc`).

```bash
otbor write letter <application-id> --tone "спокойно и по делу" --length short
otbor write letter <application-id> --save

otbor write answers <application-id> --question "Почему мы?" --question "Ваш опыт с Kubernetes?"
cat questions.txt | otbor write answers <application-id> --save

otbor write resume ./resume.txt --target-role "Platform Engineer"
cat resume.txt | otbor write resume --target-role "SRE"
```

`<application-id>` понимает префикс UUID, как остальные команды `apply`.

Общие флаги:

- `--model` — модель для харнеса;
- `--timeout` — сколько секунд ждать результат (по умолчанию 180);
- `--no-wait` — поставить job и напечатать id (с `--json` — весь job);
- `--json` — напечатать `{ job, timedOut }` в режиме ожидания.

`write` опрашивает `InferenceGet` раз в секунду до терминального статуса, как
`otbor inference run`. На `done` печатается только текст ответа. Таймаут или
ошибка печатают id, статус и, если есть, текст, и завершают команду с кодом 1.

### Сохранение в kit

`--save` работает только с уже существующим kit заявки: форму и её `formHash`
создаёт `otbor apply kit`, а writing не подменяет форму.

- **Письмо.** `write letter --save` загружает `ApplicationDetail`, требует kit
  и вызывает `ApplicationsSetKit` с прежними `answers`, `formHash`, `model`,
  `promptHash` и `costUsd`, заменяя только `letter`. Без kit команда
  завершается ошибкой.
- **Ответы.** `write answers --save` работает best effort: вытаскивает JSON из
  ответа агента (допускаются fences и текст вокруг), проверяет схему
  `Answer[]` и сохраняет ответы, сохраняя письмо и остальные поля kit. Если
  JSON не разобрался, печатается сырой ответ и объяснение, код возврата 1; если
  kit нет, сырой ответ тоже остаётся на экране.

Сохранение никогда не отправляет отклик: оно только обновляет текст в kit.

## Ограничения

- Модель вызывается только харнесом; облако не делает прямых запросов.
- `jsonSchema` для ответов пока не передаётся: формат задан промптом, разбор
  делает CLI.
- `--save` для ответов не гарантирует сохранение: при невалидном JSON ничего
  не пишется.
- Браузерного заполнения формы и отправки отклика здесь нет.
